# 프로그램의 컴파일 과정

소스 코드가 특정 OS에 종속적인 최종 기계어(실행 파일)로 변환되는 과정이다.

1. **전처리(Preprocessing):** 매크로 치환, 파일 병합, 주석 제거 등을 통해 소스 코드를 확장한다.
2. **컴파일(Compilation):** 구문과 의미를 분석하고 고수준 언어를 어셈블리어로 변환한다.
3. **어셈블(Assembly):** 어셈블리어를 기계가 직접 읽을 수 있는 목적 코드(Object Code, `.o`)로 변환한다.
4. **링크(Linking):** 여러 목적 파일과 외부 라이브러리들을 연결하여 최종 실행 파일(`.exe`, `.out`)을 생성한다.

# 프로세스

실행 중인 프로그램. 디스크에 있던 실행 파일이 메인 메모리(RAM)에 로드되어 CPU의 관리를 받기 시작하는 상태이다.

* **구성**: 기계어 코드, 현재 상태(레지스터, PC), 데이터(변수 등), 실행을 위한 스택과 힙 공간

# 프로세스의 메모리 구조

운영체제는 프로세스가 효율적으로 자원을 사용할 수 있도록 메모리를 Stack, Heap, Data, Code 4가지 영역으로 나누며, 그중 데이터 영역은 다시 Data와 BSS로 세분화하여 관리한다.

![](https://velog.velcdn.com/images/yejiiiin/post/8acf14be-57f6-459e-b0fe-83aea40ac235/image.png)


| 영역 | 특징 | 할당 시점 |
| --- | --- | --- |
| **Stack** | 지역 변수, 매개변수, 함수 리턴 주소. 함수 호출 시 생성되는 **스택 프레임** 단위로 관리 | **런타임** (동적) |
| **Heap** | 동적 데이터(C의 `malloc`, Java의 `new`) | **런타임** (동적) |
| **Data** | **초기화된** 전역 변수, 정적(static) 변수 | **컴파일** (정적) |
| **BSS** | **초기화되지 않았거나 0으로 초기화된** 전역/정적 변수 (메모리 절약을 위해 별도 관리) | **컴파일** (정적) |
| **Code** | 제어문, 함수 등 실제 실행되는 **기계어 명령어**. 수정이 불가능하도록 읽기 전용으로 설정. | **컴파일** (정적) |

## 동적 할당 영역 (Stack vs Heap)

### Stack (LIFO 구조)
* 높은 주소에서 낮은 주소 방향으로 할당된다.
* 함수 종료 시 해당 프레임의 메모리가 즉시 자동으로 해제되므로 관리가 매우 빠르고 효율적이다.
* 공간이 한정되어 있어 너무 깊은 재귀 호출이 발생하면 `Stack Overflow`가 발생한다.


### Heap
* 낮은 주소에서 높은 주소 방향으로 할당된다.
* 사용자가 직접 메모리 크기를 결정하고 할당/해제해야 한다. 
(단, Java는 GC가 대신 수행)
* 스택에 비해 상대적으로 공간이 크지만, 할당/해제 속도가 스택보다 느리다.

> 두 영역은 중간의 공유 공간을 사이에 두고 서로 마주 보며 확장되는데, 만약 두 영역이 만나게 되면 메모리 부족 상태가 된다.

## 정적 할당 영역 (Data vs BSS)

### Data Segment 
`int a = 10;` 처럼 값이 있는 변수는 실행 파일 내부에 그 값을 저장해야 하므로 용량을 차지한다.

### BSS Segment
`int a;` 처럼 초기값이 없는 변수는 "이 변수는 0으로 채울 것이다"라는 정보만 갖고 있다가, 프로세스가 실행될 때 운영체제가 한꺼번에 0으로 초기화하여 메모리에 올린다. 

실행 파일의 크기를 줄이는 효과가 있다.
