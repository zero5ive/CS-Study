# 운영체제와 컴퓨터시스템의 구조

## 운영체제의 종류
### GUI (Graphical User Interface)
그래픽을 사용하여 컴퓨터와 상호작용하는 인터페이스. windowOS, macOS등 현대의 OS가 이를 대표한다.

### CUI (Character User Interface)
사용자가 키보드만을 사용하여 문자를 기반으로 컴퓨터와 상호작용하는 인터페이스. 예전 MS-DOS가 대표적이다.

## 운영체제의 역할
운영체제의 핵심인 **커널**이 담당하는 역할이다.

- CPU 스케줄링과 프로세스 상태 관리
- 메모리 관리
- 디스크 파일 관리
- I/O 디바이스 관리

## 운영체제의 구조

- 유저 프로그램
- 인터페이스(GUI 또는 CUI)
- 시스템콜(system call)
- **커널**(I/O 드라이버, 파일시스템 등)
- 하드웨어(hardware)

> **커널 (Kernel)**: 운영체제의 핵심. 컴퓨터가 켜져 있는 동안 항상 메모리에 상주하며, 하드웨어(CPU, 메모리, 디스크 등) 자원을 관리하고 시스템 콜 인터페이스를 제공하는 등 운영체제의 중추적인 역할을 담당한다.


## 컴퓨터 시스템의 구조
- **CPU** : 인터럽트에 의해 메모리에 존재하는 명령어를 해석해서 실행하는 일꾼

- **DMA 컨트롤러 (Direct Memory Access) : CPU를 거치지 않고 I/O 장치가 직접 메모리에 접근할 수 있도록 돕는 장치.**
  - I/O 장치의 속도는 CPU보다 느리기 때문에, 데이터 전송을 CPU가 계속 관여하면 비효율적이다.
  - DMA는 CPU 대신 데이터 블록을 전송하고, **전송이 완료되었을 때만 CPU에게 인터럽트**를 걸어 CPU의 부하를 줄여준다.

- **메모리** : 전자회로에서 데이터, 상태 등을 기록하는 장치(작업장)

- **타이머** : 특정 프로그램에 시간을 할당하는 역할. 무한 루프를 방지하고 시분할 시스템(Time Sharing) 구현을 위해 정해진 시간이 지나면 인터럽트를 발생시킨다.

- **디바이스 컨트롤러** : IO 디바이스들을 제어하는 작은 CPU

- **로컬 버퍼** : 디바이스에 달려 있는 작은 메모리 (DMA는 이 버퍼의 데이터를 메인 메모리로 옮긴다)

### CPU
산술논리연산장치, 제어장치, 레지스터로 구성되어 있는 장치. 인터럽트에 존재하는 명령어를 해석해서 실행한다. 

#### 산술논리연산장치
![](https://velog.velcdn.com/images/yejiiiin/post/c4c3ea60-e938-41e8-886a-55c9b54171e4/image.png)

ALU(arithmetic and logical unit, ALU)는 덧셈, 뺄셈, 곱셈, 나눗셈 등 산술 연산과 논리 연산을 하는 회로장치이다.

#### 제어장치
제어장치(Conrtol Unit, CU)는 프로세스의 조작을 지시하며 명령어들을 읽고 해석하며 데이터 처리를 위한 순서를 결정한다.

#### 레지스터
CPU 안에 있는 매우 빠른 임시 기억 장치이다.

## 컴퓨터 시스템의 동작
### 디바이스 컨트롤러 (Device Controller)
- 각 하드웨어 장치(디스크, 키보드 등)를 제어하는 작은 CPU.

- 각 컨트롤러는 데이터를 임시 저장하기 위한 로컬 버퍼를 가지고 있다.

### 디바이스 드라이버(device driver)
운영체제(커널)의 일부로서 각 장치 제어기를 관리하는 프로그램.

#### 동작 원리

1. CPU(드라이버)가 디바이스 컨트롤러에게 명령을 내림.
2. 디바이스 컨트롤러가 작업을 수행 (CPU는 다른 일 수행).
3. 작업이 완료되면 컨트롤러가 인터럽트를 발생시켜 CPU에게 알림.

# 인터럽트

어떤 신호가 들어왔을 때 CPU를 잠깐 정지시키는 것. 키보드 입력, 디스크 작업 완료 등 하드웨어적 신호뿐만 아니라, 0으로 나누기 오류 같은 소프트웨어적 상황에서도 발생한다.

## 인터럽트 처리

운영체제는 인터럽트가 발생한 순간 **현재 작업 중인 CPU의 상태를 보존**해야 한다.

- **CPU의 상태**: 모든 레지스터값과 PC (Program Counter)

- **PCB (Process Control Block)**: 인터럽트 발생 시 현재 실행 중인 프로세스의 상태를 저장하는 메모리상의 자료구조.

### 문맥 교환 (Context Switch)

인터럽트 처리 등을 위해 현재 프로세스의 상태를 PCB에 저장하고, 다른 프로세스나 인터럽트 핸들러의 상태를 불러와 실행하는 과정을 말한다.

#### 처리 과정
![](https://velog.velcdn.com/images/yejiiiin/post/5205b655-b864-4bc8-983d-114daf81651d/image.png)

1. 발생한 인터럽트의 타입 확인한다.
   
2. 인터럽트 타입에 따라 어떤 동작이 실행되어야 하는지 결정된다. (동작이란, 각 인터럽트에 대한 **인터럽트 서비스 루틴(ISR)**을 가리킴)

2. CPU는 현재 실행 중이던 명령어를 마치고, 인터럽트 벡터를 통해 해당 ISR의 주소로 점프한다.

3. ISR 실행 후, 인터럽트 종료 시 **PCB에 저장해둔 상태를 복구**하여 원래 위치로 돌아와 순차적으로 명령어를 실행한다.


### 인터럽트 기반 IO 처리 과정
![](https://velog.velcdn.com/images/yejiiiin/post/a0ad8e57-47ac-491c-b704-d654fa175cde/image.png)

**1. I/O 작업의 시작 (CPU & Driver)**
  - **Device driver initiates I/O**: 사용자 프로그램이 시스템 콜을 통해 I/O 요청을 하면, 커널 내의 디바이스 드라이버가 하드웨어 컨트롤러에게 명령을 내린다.

**2. 하드웨어의 독립적 수행 (I/O Controller)**
- **Initiates I/O**: 장치는 명령을 받고 작업을 시작한다.

- **Interrupt Signal**: CPU는 기다리지 않고 다른 일을 한다. 장치가 작업을 마치면 CPU에게 **인터럽트 신호**를 보낸다.


**3. 인터럽트 발생과 CPU의 응답**
- **CPU receiving interrupt**: CPU는 하던 일을 멈추고 제어권을 **인터럽트 핸들러**로 넘긴다.

**4. 데이터 처리 및 복구**
- **Interrupt handler processes data**: 핸들러가 데이터를 처리하고 종료한다.

- **CPU resumes processing**: CPU는 아까 멈췄던 원래의 작업(유저 프로그램 등)으로 돌아가 중단된 지점부터 다시 실행을 이어간다.


## 인터럽트 종류
### 하드웨어 인터럽트
IO 디바이스 등 하드웨어 장치가 발생시킨 신호. 

- **비동기적(Asynchronous)**이다. CPU의 명령어 실행 흐름과 상관없이 언제든 발생할 수 있다.
- 예시: 마우스 클릭, 키보드 입력, 디스크 I/O 완료, 타이머 인터럽트 등

### 소프트웨어 인터럽트
트랩(Trap) 또는 예외(Exception)라고도 한다. 소프트웨어적으로 CPU가 스스로 발생시킨 신호.

- **동기적(Synchronous)이다.** 명령어 실행 직후 등 예측 가능한 시점에 발생한다.
- 예시: 0으로 나누기(Exception), 시스템 콜(System Call), 메모리 접근 오류 등


# 시스템 콜과 modebit
## 시스템 콜(System Call)

프로그램이 운영체제(커널)의 서비스를 요청하기 위한 인터페이스. 

사용자 프로그램은 보안상 하드웨어에 직접 접근할 수 없으므로, 시스템 콜을 통해 커널에게 대행을 요청한다. (파일 읽기, 프로세스 생성 등)

### 시스템 콜의 과정
만약 유저 프로그램이 I/O 요청을 위한 트랩을 발생시켰을 경우 다음과 같은 과정이 발생한다.

![](https://velog.velcdn.com/images/yejiiiin/post/d63652be-4a7b-4116-9f24-672f851fd887/image.png)


1. 유저 프로그램이 파일 읽기 등을 위해 `open()` 같은 함수를 호출.
2. **트랩(Trap)**이 발동되어 올바른 요청인지 확인.
3. Mode Bit이 `1`(유저)에서 `0`(커널)으로 바뀌며 커널 모드로 진입.
4. 커널 함수가 실행되어 실제 하드웨어 작업을 수행.
5. 작업 완료 후 Mode Bit이 다시 `1`로 바뀌며 유저 프로그램으로 결과 반환.

## Mode Bit (Dual Mode)
CPU 내부의 하드웨어 플래그로, 현재 실행 중인 모드를 구분하여 시스템을 보호한다.

- `1` (유저 모드): 제한된 명령어만 수행 가능. (일반 애플리케이션)

- `0` (커널 모드): 모든 시스템 자원과 명령어 접근 가능. (OS 커널)

- 동작: 시스템 콜이나 인터럽트 발생 시 하드웨어가 자동으로 0으로 바꾸고, 처리가 끝나면 1로 복귀시킨다.
