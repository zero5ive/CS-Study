
# 프로세스 (Process)
## 프로세스
실행 파일(Program)이 메모리에 적재되어 CPU를 점유하고 있는 **실행 상태의 프로그램**. Task라고도 한다. 운영체제로부터 독립된 메모리 자원을 할당받으며, 최소 하나 이상의 스레드를 가진다.

## 멀티프로세싱
여러개의 프로세스, 즉 멀티 프로세스를 통해 동시에 두 가지 이상의 일을 수행할 수 있는 것. 

![](https://velog.velcdn.com/images/yejiiiin/post/829a6584-011c-44e5-ac79-bc26c709af52/image.png)


특정 프로세스 중 일부에 문제가 발생하더라도 다른 프로세스에 영향을 미치지 않으며, 격리성과 신뢰성이 높다.

# 스레드 (Thread)

## 스레드
프로세스 내에서 실행되는 **여러 흐름의 단위**. 프로세스의 자원을 공유하면서 각자의 실행 경로를 가진다.

> Spring Boot 같은 서버 프레임워크는 기본적으로 멀티스레드 방식으로 동작한다.

## 멀티스레딩

프로세스 내 작업을 멀티스레드로 처리하는 기법. 

![](https://velog.velcdn.com/images/yejiiiin/post/49ee870c-eee0-4215-8eed-48ced820cdca/image.png)


스레드끼리 서로 자원을 공유하고 프로세스보다는 가볍기 때문에 효율성이 높다. 

하지만 한 스레드에 문제가 생기면 다른 스레드에도 영향을 끼쳐, 스레드로 이루어져 있는 프로세스에 영향을 줄 수 있는 단점이 있다.

> 브라우저는 멀티프로세스이자 멀티스레드 아키텍처를 가진 소프트웨어다.

# IPC (Inter-Process Communication)

독립적인 메모리 공간을 가지는 프로세스끼리 데이터를 주고 받고, 공유 데이터를 관리할 수 있도록 운영체제가 제공하는 통신 메커니즘. 

IPC의 종류로는 공유 메모리, 파일, 소켓, 파이프, 메시지 큐가 있다.

## 공유메모리
![](https://velog.velcdn.com/images/yejiiiin/post/6c221bab-de9c-4b69-a89c-e8071f6a20e7/image.png)

여러 프로세스가 서로 통신할 수 있도록 메모리를 공유하는 것.

메모리 자체를 공유하므로 불필요한 데이터 복사의 오버헤드가 발생하지 않아 가장 빠른 IPC 방식이다. 

단, 같은 메모리 영역을 여러 프로세스가 공유하므로 데이터 불일치가 발생할 수 있어, 뮤텍스나 세마포어를 이용한 **동기화**가 필요하다.

## 파일
디스크에 저장된 일반 파일을 읽고 쓰며 통신하는 가장 직관적이고 기본적인 방식.

디스크 I/O가 발생하므로 속도가 가장 느리고, 여러 프로세스가 동시에 파일에 접근할 때 파일 락(File Lock) 관리가 필요하다.

## 소켓
네트워크 인터페이스(TCP, UDP, HTTP 등)를 기반으로 다른 컴퓨터(네트워크)의 프로세스와 통신할 때 사용하는 방식.

## 파이프
데이터가 한쪽 방향으로만 흐르는(FIFO) 통신 채널.

파이프는 익명 파이프와 명명 파이프로 나뉜다.

### 익명 파이프 (anonymous/unnamed pipe)

이름이 없는 파이프. 통신할 프로세스를 명확히 알 수 있는 부모-자식 또는 형제 프로세스 간에만 사용할 수 있다.

파이프의 데이터 용량은 제한되어 있으며 쓰기 프로세스가 읽기 프로세스보다 더 빠르게 데이터를 쓸 수 없다.

![](https://velog.velcdn.com/images/yejiiiin/post/a78e7d01-5e23-4d8e-9e49-ab27dcf9bc5b/image.png)

파이프 하나 당 단방향 통신이므로, 양뱡향 통신을 하기 위해선 2개의 익명 파이프가 필요하다.

![](https://velog.velcdn.com/images/yejiiiin/post/b8ec4f00-82cf-42c1-a2f6-46bd11c774c1/image.png)


### 명명 파이프 (named pipe)
익명 파이프의 확장된 개념으로, 전혀 관계없는(부모-자식 관계가 아닌) 독립적인 프로세스들 사이에서도 통신할 수 있게 해주는 IPC 방식.

통신을 위해 파일 시스템에 이름을 부여하고, 프로세스들은 이 이름을 참조하여 통신한다.




![](https://velog.velcdn.com/images/yejiiiin/post/780ea929-4c18-4c25-b2f9-1019c167de39/image.png)

### 메시지 큐
메시지를 큐 자료구조 형태로 관리하는 버퍼를 만들어 통신하는 것.

![](https://velog.velcdn.com/images/yejiiiin/post/01cdaef8-e44b-4bb8-9f63-98c8b3f92640/image.png)

**과정**
1. 프로세스가 메시지를 보내거나 받기 전에 큐를 초기화한다.
2. 보내는 프로세스(sender)의 메시지는 큐에 복사되어 받는 프로세스(receiver)에 전달된다.

**장점:** 데이터를 꺼내기 전까지 큐에 보관되므로 비동기적 통신이 가능하며, 커널이 큐를 관리하므로 공유 메모리보다 동기화 처리가 직관적이고 안전하다.

**단점:** 데이터 복사(메모리 -> 큐 -> 메모리)가 일어나므로 공유 메모리보다는 속도가 느리다.

# 프로세스와 스레드의 차이

| 구분 | 프로세스 (Process) | 스레드 (Thread) |
| --- | --- | --- |
| **메모리 공유** | 독립적 (Code, Data, Heap, Stack 모두 별도) | **Code, Data, Heap 공유** / **Stack, PC Register는 독립적** |
| **자원 할당** | OS가 독립적인 주소 공간 할당 | 프로세스 내 자원을 공유하며 실행 |
| **통신 (IPC)** | 복잡함 (Pipe, Socket, Shared Memory 등 필요) | 단순함 (공유 메모리/힙 영역을 통해 직접 통신) |
| **장애 영향** | 한 프로세스 오류가 다른 프로세스에 무관함 | 한 스레드 오류가 **전체 프로세스를 종료**시킬 수 있음 |
| **전환 비용** | 높음 (Context Switching 시 캐시 초기화 등) | 낮음 (공유 자원이 많아 전환 속도가 빠름) |

> 스레드가 독립적인 실행 흐름을 가지려면 각자 어떤 명령어를 실행 중인지 기록하는 PC 레지스터와, 함수 호출 시 발생하는 지역 변수 및 복귀 주소를 저장하는 Stack이 별도로 존재해야만 컨텍스트 스위칭 이후에도 작업을 정상적으로 재개할 수 있다.
