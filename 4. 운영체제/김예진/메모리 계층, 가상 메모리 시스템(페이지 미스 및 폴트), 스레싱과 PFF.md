# 메모리 계층 (memory hierarchy)

메모리 계층 구조는 속도, 용량, 비용의 **트레이드오프(Trade-off)** 관계를 해결하기 위해 설계되었다.

| 계층 | 구성 요소 | 특징 | 휘발성 | 용량 및 속도 |
| --- | --- | --- | --- | --- |
| **최상위** | 레지스터 | CPU 내부 위치, 회로가 가장 복잡함 | 휘발성 | 가장 적음 / 가장 빠름 |
| **상위** | 캐시 (L1, L2, L3) | CPU와 RAM 사이의 속도 차이 완화 | 휘발성 | 적음 / 빠름 |
| **중위** | 주기억장치 (RAM) | 실행 중인 프로세스의 데이터 저장 | 휘발성 | 보통 / 보통 |
| **하위** | 보조기억장치 (SSD/HDD) | 데이터를 영구적으로 저장 | 비휘발성 | 가장 많음 / 가장 느림 |

## 계층 구조가 존재하는 이유

우리가 캐시나 가상 메모리를 효율적으로 쓸 수 있는 이유는 프로그램이 메모리의 특정 영역을 집중적으로 참조하는 **지역성**의 원리 때문이다.

1. **시간적 지역성 (Temporal Locality)**: 최근에 참조된 데이터는 가까운 미래에 다시 참조될 가능성이 높음. 
(예: 루프문의 인덱스 변수)

2. **공간적 지역성 (Spatial Locality)**: 참조된 데이터와 인접한 데이터가 참조될 가능성이 높음. 
(예: 배열의 연속된 요소 접근)

# 가상 메모리 (Virtual Memory)

가상 메모리는 물리적 메모리(RAM)의 한계를 극복하기 위해 OS가 제공하는 **메모리 관리 기법**이다. 

가상 주소는 MMU와 페이지 테이블에 의해 실제 주소로 변환된다.



## 가상 메모리의 장점


1. **메모리 효율적 사용 (Demand Paging)**: 
필요한 시점에만 페이지를 로드하여 RAM 낭비를 줄인다.

2. **프로세스 간 메모리 보호**: 
독립된 가상 주소 공간을 통해 한 프로세스가 다른 프로세스나 OS 영역을 침범하지 못하게 격리한다.

3. **메모리 접근 제어**: 
페이지 테이블에 권한 비트(Read, Write, Execute)를 두어 허가되지 않은 접근을 하드웨어 수준에서 차단한다. 버퍼 오버플로우나 코드 인젝션 같은 보한 위협을 예방한다.



## 주요 구성 요소

* **페이지(Page)**: 가상 메모리를 나누는 최소 단위.
* **프레임(Frame)**: 실제 물리 메모리를 나누는 최소 단위.
* **페이지 테이블(Page Table)**: 가상 주소와 물리 주소를 매핑하는 자료구조.

![](https://velog.velcdn.com/images/yejiiiin/post/f2f6719b-bee9-4caa-9d2e-4c1433774041/image.png)
* **MMU (Memory Management Unit)**: CPU가 보낸 가상 주소를 물리 주소로 변환해주는 하드웨어 장치.
* **TLB (Translation Lookaside Buffer)**: 페이지 테이블의 일부를 캐싱하는 하드웨어. 주소 변환 속도를 획기적으로 높여줌.
![](https://velog.velcdn.com/images/yejiiiin/post/f2ba68fe-c2aa-47a5-8194-619ab65ed1a2/image.png)
>원래 가상 메모리 시스템에서 데이터를 가져오려면 메모리(RAM)에 두 번 접근해야 한다. 한 번은 실제 주소를 찾기 위해 페이지 테이블을 확인하러 가고, 그 다음 실제 데이터를 가져오러 가야 하는데, TLB hit가 발생하면 메모리 내의 페이지 테이블을 거치지 않아도 된다.

# 페이지 미스와 페이지 폴트


## 페이지 미스(Page Miss)
찾으려는 데이터가 현재 계층(캐시나 RAM)에 없는 상태를 뜻하는 포괄적인 개념.

## 페이지 폴트(Page Fault)
페이지 미스 중에서도 프로세스가 요청한 페이지가 현재 RAM(물리 메모리)에 없는 상태. 이때 OS는 하드웨어 인터럽트인 **트랩**을 발생시켜 제어권을 넘겨받는다.

모든 페이지 폴트는 페이지 미스로 인해 발생하지만, 모든 페이지 미스가 페이지 폴트로 이어지는 것은 아니다.

* **예외 1 (권한 오류)**: 
해당 페이지에 대한 접근 권한이 없거나 잘못된 접근(예: 쓰기 금지된 페이지에 쓰기 시도)이 시도되었을 경우, OS는 데이터를 로드하는 대신 오류로 처리하고 요청을 거부한다.

* **예외 2 (프리페칭 최적화)**: 
성능 최적화를 위해 미리 읽어온 데이터가 사용되지 않고 교체될 경우 미스는 발생하지만, 사용되지 않아 실제 폴트 처리 과정으로 이어지지 않을 수 있다.


### 페이지 폴트 해결 과정

1. CPU가 가상 주소로 메모리에 접근 시도.
2. **페이지 테이블**에서 해당 페이지가 '유효하지 않음(Invalid)'임을 확인.
3. **트랩** 발생 -> OS가 제어권 획득.
4. OS는 디스크의 **스왑 영역(Swap area)**에서 해당 페이지를 찾음.
5. 물리 메모리의 빈 **프레임**을 확보 후 페이지 적재 (**Swap-in**).
   * *빈 프레임이 없다면?* 
   **페이지 교체 알고리즘**을 통해 기존의 한 페이지를 선택해 디스크로 내보냄 (**Swap-out**).


6. 페이지 테이블을 갱신 (Valid 비트로 변경).
7. 중단되었던 명령어를 다시 실행.

# 스레싱 (Thrashing)

스레싱은 너무 잦은 페이지 폴트로 인해 CPU가 실제 작업보다 **페이지 교체(I/O)** 에 더 많은 시간을 쓰는 상태이다.

![](https://velog.velcdn.com/images/yejiiiin/post/3d5315e3-ab76-4aa4-8d0f-3215e4f550a1/image.png)



**원인**: 
메모리에 너무 많은 프로세스가 동시에 올라가 있어(다중 프로그래밍의 정도가 너무 높음), 각 프로세스가 필요한 최소한의 프레임도 확보하지 못할 때 발생.

**해결책**: 
* **작업 세트(Working Set)**: 
프로세스가 특정 시간 동안 자주 참조하는 페이지 집합을 메모리에 상주시켜 페이지 폴트를 막음.
* **PFF(Page Fault Frequency)**: 
페이지 폴트 빈도를 모니터링하고 상한선과 하한선을 두어 할당되는 프레임 수를 동적으로 조절.


## PFF (Page Fault Frequency)

**PFF**는 각 프로세스의 페이지 폴트 발생 빈도를 모니터링하여, 메모리 프레임 할당량을 동적으로 조절하는 기법이다. 시스템이 **스레싱(Thrashing)** 상태에 빠지지 않도록 한다.

* **상한선(Upper Bound) 초과**: 
페이지 폴트가 너무 자주 발생하면 프로세스에 할당된 프레임이 부족한 것이므로, OS는 해당 프로세스에 프레임을 더 할당하여 **작업 세트(Working Set)** 를 확장시킨다.

* **하한선(Lower Bound) 미달**: 
페이지 폴트가 거의 발생하지 않으면 프레임이 과하게 할당된 상태일 수 있으므로, OS는 프레임을 일부 회수하여 다른 필요한 프로세스에 재할당한다.
