# PCB (Process Control Block)

운영체제가 프로세스를 제어하고 관리하기 위해 해당 프로세스에 대한 메타데이터를 저장해 두는 자료구조.

프로세스가 생성될 때 운영체제에 의해 고유의 PCB가 생성되고, 프로세스가 종료되면 제거된다.

* **저장 위치:** **커널 공간(Kernel Space)의 메모리 영역**에 저장되며, 사용자 모드에서는 접근할 수 없고 커널 모드에서만 접근 및 수정이 가능하다.

## PCB 구조

![](https://velog.velcdn.com/images/yejiiiin/post/a51b0ea7-96b9-46d8-88f6-25d27d20b9ac/image.png)


1. **프로세스 상태 (Process State):** 생성, 준비, 실행, 대기, 종료 등의 상태 정보.
  
2. **프로세스 ID (PID):** 각 프로세스를 식별하는 고유 번호.

3. **프로그램 카운터 (PC):** 이 프로세스가 다음에 실행할 명령어의 메모리 주소를 가리키는 포인터. 컨텍스트 스위칭 시 어디까지 실행했는지 기억하는 역할이다.

4. **레지스터:** 누산기, 스택 포인터 등 CPU가 작업 중이던 레지스터 값들.

5. **메모리 제한:** 프로세스가 사용하는 가상 메모리 정보, 페이지 테이블 포인터 등.

6. **열린 파일 정보:** 프로세스가 사용 중인 열려있는 입출력 장치들 및 파일들

## 프로세스 상태 (Process State)
![](https://velog.velcdn.com/images/yejiiiin/post/5e460f36-401a-47ca-a14e-6a894c04cb04/image.png)

프로세스는 생성, 준비, 실행, 대기, 종료 등의 상태를 갖는다.

### **NEW (생성 상태)**
프로세스가 이제 막 생성되어 운영체제로부터 PCB를 할당받은 상태. 아직 메인 메모리에 올라가지는 않은 상태다.

* **`fork()`:** 부모 프로세스가 자신의 주소 공간과 자원을 그대로 복사하여 새로운 자식 프로세스를 생성하는 시스템 콜. (PID는 새로 부여됨)

* **`exec()`:** 현재 프로세스의 메모리 공간을 새로운 프로그램 이미지로 완전히 덮어쓰는 시스템 콜. (PID는 유지됨)

### **READY (준비 상태)**
프로세스가 실행에 필요한 모든 자원(메모리 등)을 할당받고, **CPU를 할당받기를 레디 큐(Ready Queue)에서 기다리는 상태**.

### **RUNNING (실행 상태)**
준비 상태에 있던 프로세스가 CPU 스케줄러에 의해 선택(Dispatch)되어, **실제로 CPU를 점유하고 명령어를 실행하고 있는 상태**.

### **WAITING / BLOCKED (대기/차단 상태)**
실행 중이던 프로세스가 I/O 작업(키보드 입력, 파일 읽기 등)을 요청하거나 특정 이벤트가 발생하기를 기다리며 **CPU를 반납하고 대기 큐(Wait Queue)에서 멈춰 있는 상태**. 

I/O 작업이 완료되면 다시 READY 상태로 돌아간다.


* **Blocked Suspended (대기 지연 상태)**
프로세스가 Blocked 상태에서 대기하고 있던 중, 메모리 부족으로 인해 통째로 디스크로 스왑 아웃된 상태.

* **Ready Suspended (준비 지연 상태)**
Ready 상태의 프로세스가 메모리 부족으로 디스크로 스왑 아웃된 상태이거나, Blocked Suspended 상태인 프로세스의 I/O 작업이 끝났지만 여전히 메모리에 올라오지 못한 상태.

### TERMINATED (종료 상태)
프로세스 실행이 완료되어 CPU와 메모리 등 할당된 모든 자원을 반납하고, 운영체제가 PCB를 삭제하려 하는 상태.

* **정상 종료(Exit):** 프로세스가 할 일을 모두 마치고 자연스럽게 종료되는 경우.

* **비정상 종료(Abort/Kill):**
   * 부모 프로세스가 자식 프로세스를 강제로 종료시키는 경우.
   * 자식 프로세스가 할당된 자원 한계치를 초과하거나, 심각한 오류(예: 0으로 나누기, 잘못된 메모리 참조 등)가 발생한 경우.
   * 사용자가 `kill` 명령어 등으로 강제 종료하는 경우.



# 컨텍스트 스위칭 (Context Switching)

현재 실행 중인 프로세스(또는 스레드)의 상태(Context)를 PCB에 저장하고, 다음에 실행할 프로세스의 상태를 PCB로부터 읽어와 CPU의 레지스터에 적재하는 과정.

![](https://velog.velcdn.com/images/yejiiiin/post/220bf2aa-002e-486d-90e1-7efca3c2d2cf/image.png)


## 발생 원인
* **멀티태스킹 (타임 슬라이스 만료):** CPU 할당 시간(Time Quantum)을 다 쓴 경우 (라운드 로빈 스케줄링 등).

* **인터럽트 (Interrupt):** 하드웨어/소프트웨어 인터럽트 발생 시.

* **I/O 요청:** 프로세스가 디스크 읽기/쓰기 등 I/O 작업을 요청하여 대기 상태로 전환될 때.

## 컨텍스트 스위칭의 오버헤드 (비용)


1.  **레지스터 저장 및 복원 비용:** 

  CPU는 기존 작업의 상태(PC, 레지스터 등)를 PCB에 저장하고 새 작업의 상태를 로드해야 하며, 이 작업 자체에 CPU 사이클이 소모되어 유휴 시간이 발생한다.

2.  **메모리 캐시 초기화 및 캐시 미스:** 

    * 프로세스가 변경되면 사용하는 가상 메모리 공간이 달라지기 때문에, 주소 변환을 돕는 캐시인 **TLB(Translation Lookaside Buffer)를 완전히 비워야(Flush) 한다.**

    *  CPU 내부의 L1, L2 캐시 등도 무효화될 확률이 높아져, 새로운 프로세스 실행 초기에 **캐시 미스(Cache Miss)** 가 발생하여 메모리 접근 속도가 크게 떨어진다.

## 프로세스 vs 스레드 컨텍스트 스위칭

* **프로세스 컨텍스트 스위칭:** 
  서로 다른 독립적인 메모리 공간을 가지므로, 위에서 언급한 캐시 초기화(TLB Flush) 및 메모리 매핑 변경 오버헤드가 크게 발생한다.

* **스레드 컨텍스트 스위칭:** 
스레드는 속해 있는 프로세스의 메모리 영역(Code, Data, Heap)을 공유하고, 스택(Stack) 영역과 레지스터만 독립적으로 가진다.

  스레드 정보는 **TCB(Thread Control Block)** 에 저장 및 관리된다.

  > 메모리를 공유하기 때문에 **TLB나 캐시를 비울(Flush) 필요가 없어** 컨텍스트 스위칭 속도가 훨씬 빠르고 비용이 적다.
